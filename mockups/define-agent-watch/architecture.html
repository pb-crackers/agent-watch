The harness

Pi runs as usual. Agent Watch watches the conversation, asks Jev what went wrong, changes the harness, and learns from what happens next.

The autonomous loop

One improvement at a time · no rating prompts
01 / SignalPi conversationUser corrections, requests, agent responses, tools, skills, errors.
02 / CaptureObserverPi extension streams events to a local background process.
03 / FocusSliding windowCurrent task + recent turns, not the entire transcript each time.
04 / RouteJev decision treeChange warranted? Which observed component? What change direction? Each answer selects the next question.
05 / DecideControllerWait for a persistent signal. Enforce limits in code.
06 / DraftHeadless PiDrafts 2–3 distinct small harness patches in isolation; code rejects unsafe ones.
07 / SelectJev choosesIs any draft suitable? Which validated patch—or none? Pi does not pick its own fix.
08 / LearnApply + watchSnapshot and log the chosen diff. Later turns decide keep or rollback.
↶Every new user message and tool result becomes fresh feedback for the next window. The conversation itself is the evaluation signal.
Visible in Pi + browserLive status, findings, active change, and history. Nothing is injected into the observed agent’s context.
Readable on disk.agent-watch/changes.md records the candidates, Jev’s selection, applied diff, and rollback history.

Who does what

Jev decides in stages

Successive questions choose whether to change, where, how, which exact diff, and whether it helped. Uncertain branches stop. Jev never writes code.

Pi drafts alternatives

A separate headless run drafts distinct isolated diffs to instructions, settings, prompts, skills, or extensions. It cannot choose what goes live.

Code enforces

File boundaries, redaction, rate limits, atomic writes, conflict checks, snapshots, and rollback are deterministic—not model decisions.

The user can inspect

CLI and local web UI expose the live state. An emergency pause stops improvements and restores an unverified change.

The boundary

  • Only project-local Pi harness files can be changed; application source and global config stay untouched.
  • Secrets are redacted before local storage or Jev requests.
  • One candidate at a time. Every applied diff has a previous snapshot and an entry in .agent-watch/changes.md.
  • If Agent Watch or Jev is unavailable, Pi keeps working.
